# Як випустити нову версію та оновити додаток

Додаток сам перевіряє [GitHub Releases](../../releases) цього репозиторію. Коли там з'являється версія новіша за встановлену, користувач бачить підказку, а в **Меню → Перевірити оновлення** (також у «Налаштуваннях» і «Про додаток») може завантажити та встановити APK. Після оновлення додаток показує повідомлення «Додаток оновлено до версії X» разом зі списком змін.

## Одноразове налаштування (робиться один раз)

Android оновлює додаток лише тоді, коли нова версія підписана **тим самим ключем**, що й встановлена. Тому потрібен один постійний ключ, який зберігається в GitHub Secrets.

1. Створіть ключ (потрібен JDK 17+):
   ```bash
   ./tools/generate-keystore.sh todolist-release.jks todolist
   ```
   Скрипт попросить пароль і виведе, що додати в Secrets. **Збережіть файл `.jks` і пароль у надійному місці** — без них оновити встановлені додатки буде неможливо (лише видалити й поставити заново). У репозиторій файл не потрапить (`.gitignore`).
2. У репозиторії GitHub: **Settings → Secrets and variables → Actions → New repository secret**. Додайте чотири секрети:

   | Секрет | Значення |
   |---|---|
   | `KEYSTORE_BASE64` | вміст `.jks` у base64: `base64 -w0 todolist-release.jks` (macOS: `base64 -i todolist-release.jks`) |
   | `KEYSTORE_PASSWORD` | пароль, який ви обрали |
   | `KEY_ALIAS` | `todolist` (або те, що вказали вище) |
   | `KEY_PASSWORD` | той самий пароль |
3. Увімкніть Actions у репозиторії (вкладка **Actions**), якщо вони вимкнені.
4. Застосуйте правила бази з [`docs/firebase-rules.json`](firebase-rules.json) (Firebase Console → Realtime Database → Rules). Спочатку перевірте їх у **Rules Playground**.

## Випуск версії

```bash
git tag v1.2.0
git push origin v1.2.0
```

Workflow **Release** сам: перевірить тег (формат `vМ.м.п`), запустить тести (якщо вони падають — релізу не буде), збере підписаний APK, перевірить підпис, опублікує реліз із файлами `ToDoList-v1.2.0.apk` та `.sha256` і додасть у опис «що нового» (з комітів) та звіт про тести.

Версії: `versionName` = `1.2.0`, `versionCode` = `10200` (мажорна·10000 + мінорна·100 + патч; мінорна й патч — до 99). Номер завжди має зростати.

> **Перше оновлення старих копій.** Копії, встановлені з APK, зібраного іншим ключем (наприклад, з Android Studio), оновитися «поверх» не зможуть — Android відмовить. Додаток покаже відповідне пояснення; такі копії треба один раз видалити й встановити APK з релізу (завдання зберігаються в акаунті Firebase). Далі оновлення працюватимуть.

## Автоматичні звіти

| Що | Коли | Де дивитися |
|---|---|---|
| **CI** — тести, lint, збірка debug APK | кожен push і pull request | вкладка Actions → підсумок запуску; звіти — у артефактах |
| **Release** — звіт про тести в описі релізу | кожен тег `v*` | сторінка релізу |
| **Weekly report** — тести, lint, кількість комітів, останній реліз | щопонеділка (~05:17 UTC) і вручну | issue **Automatic weekly report** (підпишіться на нього, щоб отримувати звіти на пошту) |

## Якщо щось пішло не так

- *Release падає на кроці «Check that signing secrets exist»* — не додано один із чотирьох секретів.
- *«The APK is signed with the debug key»* — секрети не підхопилися; перевірте назви.
- *У додатку «Помилка мережі» / «GitHub обмежує запити»* — публічний API GitHub без токена має ліміт; спробуйте пізніше.
- *«Контрольна сума не збігається»* — файл пошкоджено під час завантаження; він автоматично видаляється, спробуйте ще раз.
- *Android просить дозвіл «Встановлення невідомих додатків»* — це нормально для оновлення поза Google Play; дозвіл вмикається один раз для цього додатка.
