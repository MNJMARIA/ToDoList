# Знайдені проблеми та що з ними зроблено

Підхід: спершу тести (специфікація → червоні), потім логіка (зелені), потім перенесення в Android-код. Логіка без залежностей від Android лежить у `app/src/main/java/com/example/todolist/core`, тести — `app/src/test` (128 тестів). Частину помилок відтворено окремим скриптом до виправлення; тести з назвами «Regression» повторюють реальні дефекти старого коду.

## Помилки, що ламали роботу

| Де (було) | Проблема | Що зроблено |
|---|---|---|
| `MonthFragment.convertDateAndTimeToMillis` | формат `yyyy-MM-dd` не збігався з реальним `dd/MM/yyyy` → дедлайн завжди `0` | один розбір дат (`TaskDateTime`), строгий, не залежить від локалі |
| `DeadlineNotificationManager` | усі нагадування мали однаковий requestCode `0` — нове нагадування стирало попереднє; сповіщення «за 3 дні» ставилося в минуле й спрацьовувало одразу | по одному будильнику на завдання (`ReminderScheduler`, `ReminderPlanner`), відновлення після перезавантаження й оновлення |
| `SettingsFragment.cancelAllNotifications` | `PendingIntent` без `FLAG_IMMUTABLE` — на Android 12+ (targetSdk 34) падає з `IllegalArgumentException`; крім того, скасовував лише «нульовий» будильник | вимкнення скасовує всі будильники, перемикач реально працює; запит `POST_NOTIFICATIONS` на Android 13+ |
| `DayFragment.onDoneItemClicked` + `TaskAdapter` | після «виконано» через 1 с викликався ще й `onDeleteItemClicked` → лічильники зменшувались повторно; подвійний дотик нараховував бали двічі | завершення/видалення — транзакція, що спрацьовує один раз (`TaskRepository`) |
| статистика | читання-зміна-запис без транзакцій, від’ємні значення | транзакції + `StatsRules` + одноразове «лікування» старих даних (`reconcileStatsOnce`) |
| `AchievementUtils` | `score == threshold` — досягнення пропускалось, якщо бали перескочили поріг, або показувалось повторно | порівняння попереднього й нового результату (`AchievementRules.newlyUnlockedIndex`) |
| `TaskAdapter` | `NullPointerException` для завдань без дати/пріоритету; читання `parts[2]` після перевірки `length >= 2`; стара позиція в обробниках; «залишки» зеленого кольору на перевикористаних картках | безпечний розбір, `getBindingAdapterPosition`, скидання вигляду |
| `SplashFragment`, `SignInFragment` | якщо профілю в базі немає — користувач назавжди залишався на заставці / входу | профіль створюється автоматично, помилка мережі не блокує вхід |
| `AchievementsFragment`, `HomeFragment` | `getValue(Integer.class)` без перевірки на `null`; новий користувач без статистики бачив порожній екран | значення за замовчуванням |
| `DayFragment`/`MonthFragment` | у «Дні» після кожного збереження, у «Місяці» після кожної зміни дати додавався ще один слухач Firebase; слухачі не знімались | один слухач на екран, знімається в `onDestroyView` |
| `MonthFragment` | порівняння дат як рядків: `05/11/2026` ≠ `5/11/2026` | порівняння за календарним днем (`sameDay`) |
| вибір дати | порівнювались моменти часу — «сьогодні» могло бути відхилено | порівняння днів; «сьогодні» дозволено |

## Безпека й дані

| Проблема | Що зроблено |
|---|---|
| Пароль зберігався у відкритому вигляді в `Users/<uid>/password` (і показувався в профілі) | поле більше не пишеться й видаляється при завантаженні профілю; перевірка пароля — через повторну автентифікацію Firebase; зміна пароля — `updatePassword`. **Дії для власника:** пароли, що вже були в базі, вважайте скомпрометованими — попросіть користувачів змінити їх; застосуйте правила з `docs/firebase-rules.json`; обмежте API-ключ у Google Cloud Console (`google-services.json` у репозиторії публічний) |
| E-mail у профілі змінювався лише в базі, але не в Firebase Auth | поле лише для читання |
| `READ_EXTERNAL_STORAGE` без потреби; експортований ресивер | прибрано; ресивери `exported=false` |
| Незашифрований HTTP-трафік дозволений | `usesCleartextTraffic=false` |

## Дрібніші виправлення

- Діалог завдання: порожня назва (повідомлення було жорстко задано українською), довжина ≤ 200, коректне поле введення (було `textEmailAddress`), пріоритет за позицією списку, а не за перекладеним текстом; категорія зі «старою» мовою зберігається.
- «Зв'язок із нами» більше не пише «Повідомлення надіслано» — відкривається поштовий застосунок, відправлення підтверджує користувач; рядки локалізовано.
- Хардкод «Got it!» → рядок у 6 мовах; зворотна навігація після реєстрації/виходу (`popUpTo`).
- Екран «Про додаток» прокручується й показує реальну версію.

## Що додано

- Оновлення з GitHub Releases: перевірка, завантаження з прогресом, SHA-256, звірка підпису, встановлення; повідомлення «Додаток оновлено» (сповіщення + діалог зі списком змін).
- CI (тести, lint, збірка), реліз за тегом, тижневий звіт — див. `RELEASING.uk.md`.

## Свідомо не змінено / відкрито

- Категорія завдання зберігається як локалізований текст (зміна мови не перекладає старі завдання). Правильніше зберігати ключ — потребує міграції даних.
- Бали рахує клієнт, тому їх теоретично можна підробити; захист потребує серверної логіки (Cloud Functions).
- Звіти про збої (crash reporting) не підключено.
- Архітектура не перероблялась на MVVM, як заявлено в README; лише винесено логіку й доступ до даних.
